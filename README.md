# 架空の動画フィード デモ（4層構成 / ローカル完結）

> **免責事項**: このディレクトリのコードは全て、動画プラットフォームの
> 「アテンション・ハッキング」の仕組みを学習・分析するための**架空・簡略化された実装**です。
> 特定企業の実装を示すものではありません。外部APIには一切接続せず、
> すべてローカル（SQLite + 手元のPythonプロセス）だけで完結します。

## 何が動くのか

ブラウザで動画フィードっぽい画面を操作すると、裏側で

1. **UI層**（`templates/index.html`, `static/app.js`, `static/style.css`）
   - 自動再生（動画が終わると5秒カウントダウンして次へ）
   - 無限スクロール（`IntersectionObserver` で下端に来たら次ページを取得）
   - 進捗バー（再生時間に応じて伸びる）
   - ログイン表示（ユーザー選択 → A/B群を画面に表示）

2. **計測層**（`events.py`）
   - `play` / `complete` / `skip` / `like` / `purchase` / `win` / `lose`
     の各イベントをサーバーに送り、`events` テーブルに生ログとして記録

3. **推薦・最適化層**（`recommender.py`）
   - スコア計算（嗜好ベクトル × Elo × 完了率 × いいね率）
   - 並べ替え
   - 探索（Exploration）… B群だけ、あえてスコアの低い動画を混ぜる
   - ユーザー情報更新（反応のたびに嗜好ベクトルをオンライン更新）
   - A/Bテスト（ユーザーごとに A: 素直な並び / B: 探索あり、を割り当て）

4. **基盤層**（`db.py`, `model_training.py`, `external_api_stub.py`）
   - データベース（SQLite 1ファイル `demo.db`）
   - イベント処理（`events.py` が受信→集計テーブル更新までを担当）
   - 外部レコメンドAPI（`external_api_stub.py`。実際には呼ばず、常にローカルへフォールバック）
   - モデル訓練（`model_training.py`。貯まったイベントから重みをロジスティック回帰で再学習するバッチ）

が動きます。全部つながっているので、「いいねやスキップを繰り返す→嗜好ベクトルが動く→
次のフィードの並びが変わる→`model_training.py` を実行するとモデル重み自体も更新される」
という一連のループを手元で観察できます。

## 起動方法

```bash
cd demo
pip install -r requirements.txt
python app.py
```

ブラウザで `http://127.0.0.1:5000` を開き、ユーザーを選んでログインしてください。
初回起動時に `demo.db` が自動生成され、架空のユーザー5人・動画60本が投入されます。

## モデルの再学習（オフラインバッチ）を試す

しばらくフィードを操作してイベントを溜めたあと、サーバーを立てたまま別ターミナルで:

```bash
cd demo
python model_training.py
```

`events` テーブルから完了/スキップ/いいねの実績を使って重みを再計算し、
`model_weights` テーブルを更新します。以降のフィード取得から新しい重みが反映されます。

## A/Bテストの中身を覗く

画面右の「デバッグ: 推薦・最適化層の内部状態」パネルで、自分の

- A/B群
- カテゴリ別の嗜好ベクトル
- 現在のグローバルモデル重み

をいつでも確認できます。ユーザーを切り替えてログインし直すと、A群とB群で
フィードの並び方の"ばらつき方"が違うことが体感できます。

## ファイル構成

```
demo/
  app.py                 # UI層のホスト & APIルーティング
  db.py                  # 基盤層: SQLiteスキーマ定義
  seed_data.py            # 架空データの初期投入
  events.py                # 計測層 + イベント処理
  recommender.py           # 推薦・最適化層（スコア/並替/探索/A-B/Elo）
  model_training.py        # 基盤層: オフラインバッチ学習
  external_api_stub.py     # 基盤層: 外部レコメンドAPIの差し替え口（未使用）
  templates/index.html     # UI層の画面
  static/app.js            # UI層のロジック + 計測イベント送信
  static/style.css         # 見た目
```


## 振り返り
 
このプロジェクトを通じて、
推薦システムはユーザー行動を継続的に観測しながら
評価指標を更新する仕組みであることを学んだ。
 
次回は、オペラント条件づけにおける変動スケジュールも組み込みたいと思った。
